Review and multi-step tools

  • review_changes (or /review) reviews uncommitted changes for correctness, security, and quality. It runs an independent read-only reviewer per dimension, each in a fresh context, then a skeptical verifier that re-checks every candidate against the real code and drops false positives, and reports the confirmed findings. Findings show up under the review as soon as each reviewer reports them, marked unverified, and update in place as the verifier confirms or rejects them; once the review ends, rejected findings fold into a "dropped as false positives" line you can expand. Click a finding to see why it matters and the suggested fix. Scope it to a base branch or specific paths, raise effort to high to verify each finding with several independent skeptics, or pass model to run the reviewers and verifiers on a cheaper sibling model.
  • todo_write keeps a task list for multi-step work, rendered live in the transcript.
  • pr_sweep tracks batch pull-request work (author new PRs from a task list, or process a batch of existing open PRs).
  • show_images shows you image files the agent produced, such as screenshots of an app or rendered mockups. In the desktop app they appear as a captioned gallery: click any image to open it full size, step through the set with the arrow keys, compare it with a "before" image using a slider when the agent paired one, copy it, save it, show it in the Files panel, or open the file in its default app. In the terminal each image is a clickable link to its file. It only reads image files (PNG, JPEG, GIF, or WebP, up to 5 MB each, 12 per gallery) inside the project, so it never asks for approval. Images go to the model scaled down to at most 1568 pixels on their long side; the chat keeps the full-size originals.
  • render_mockup (desktop app) turns an HTML mockup file in the project into screenshots without a dev server, in the sizes and themes asked for (desktop, tablet, or mobile, light or dark, or a custom size), and shows them as a gallery marked "Mockup from code". The page runs in a hidden, locked-down browser: it can load its own files from the project folder, but nothing from the network or from elsewhere on your computer. It writes nothing, so it never asks for approval.
  • view_localhost (desktop app) loads a page from a dev server running on your computer in a hidden browser and shows the agent a screenshot plus the page's visible text and console output. It can also run steps first (fill a field, click or double-click, press a key such as Enter or Escape, wait for an element, check that some text is or isn't shown), so the agent can try a flow such as logging in or submitting a form and get a pass or fail for each step. It can also capture the page in several viewports or color schemes in one call (desktop, tablet, or mobile, light or dark, or the full page height), shown as a gallery marked "Running app"; steps then run with only one of them. Each call starts from a fresh page load, so a flow runs within one call. Text typed into a password field is never shown back to the agent. Every call asks for approval. A call with steps is approved separately from plain views, and the approval lists each step (never the text being typed). Steps can't download files, upload files, or use your camera, microphone, or location, and the page can't leave localhost.
