Houston docs

How to use Houston, the cross-platform coding agent that works with your own model. These pages describe Houston v0.9.0, the latest release.

Getting started

  • Getting started in the desktop app

    On a first launch the welcome screen shows a three-step Get started checklist: connect a model...

  • What Houston is

    Houston is a coding agent that runs on the user's own machine and works inside a single project directory.

  • Clients (where Houston runs)

    All clients share one agent core, so tools, permissions, and skills behave the same across them.

  • Models

    Bring any model with your own key: Anthropic, OpenAI, Google, any OpenAI-compatible endpoint, or a local model runtime.

  • Settings and keys

    Settings covers providers and keys, web search, approval mode and permission rules, hooks, MCP servers, additional folders, context threshold, appearance...

Working with the agent

  • The terminal composer

    The interactive terminal's composer is a full line editor, so a message can be as long as it needs to be.

  • Slash commands

    Type / in the composer for the command menu.

  • Typing while it works (steering)

    You do not have to wait for a turn to finish before saying the next thing.

  • How long a turn runs

    A turn has a step budget (40 by default; each model reply is one step).

  • How hard the model thinks (/reasoning)

    /reasoning shows the current thinking effort; /reasoning high (or off, low, medium, xhigh) sets it.

  • Being told when it needs you

    A long run can block on an approval, a question, or a plan, and then it is just waiting.

  • Running your own commands (!)

    Type ! followed by a command to run it in your own shell, without leaving the session: !git status, !npm test. Output streams as it happens.

  • Remembering an instruction (#)

    Start a line with # to turn it into a standing instruction: # always run the linter before committing.

  • Side chat (/btw)

    The side chat answers a quick question about the open chat without adding anything to it.

Reviewing and undoing changes

  • Seeing what the tools did

    While a turn runs, each tool result collapses to one line: the transcript is a conversation, not a log.

  • What actually ran (the receipt)

    A turn that ran checks or changed files ends with a line marked Recorded by Houston under the agent's last message, for example No tests ran · install...

  • Editing files while it works

    You can keep working in your own editor while a turn runs.

  • Undoing a turn, and seeing what changed

    /undo covers the last turn's file writes only. It does not undo shell commands, and it does not touch git history.

  • Review and multi-step tools

    review_changes (or /review) reviews uncommitted changes for correctness, security, and quality.

  • Diagrams and visuals in replies

    In the desktop app, the agent can answer with pictures as well as text.

Extending Houston

  • Skills

    A skill is a reusable instruction bundle at .houston/skills/<name>/SKILL.md, with front-matter name and description and a body of instructions.

  • Custom subagents

    Drop a Markdown file in .houston/agents/<name>.md to define a specialized subagent: front-matter description plus a system-prompt body.

  • Hooks

    Hooks (Settings, Hooks) run your own shell commands at set points in the agent loop.

  • Plugins

    Drop a JS file in .houston/plugins/ to register observational lifecycle hooks: houston.on('onToolStart' | 'onToolResult' | 'onUserMessage', fn), for...

  • MCP servers

    Connect Model Context Protocol servers in Settings: a local stdio process or a remote HTTP (streamable) or SSE endpoint.
