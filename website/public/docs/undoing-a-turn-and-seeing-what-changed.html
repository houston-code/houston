Undoing a turn, and seeing what changed

On this page

  • Shipping changes (desktop app)
  • Prompts Houston writes for you
CommandDoes
/undoputs back the files the last turn changed
/redore-applies them
/changes (or /diff)summarizes everything different in the working tree: each file with its status and lines gained and lost, plus a total
  • Nothing to set up. Houston snapshots every write before it happens.
  • Best with auto-approve modes, where edits land without a prompt: "that was wrong, put it back" is one word rather than a hand revert.
  • Limits. /undo covers the last turn's file writes only. It doesn't undo shell commands, and it doesn't touch git history.
  • /changes is the natural question after a long autonomous run.

Shipping changes (desktop app)

When the working tree has changes, the bar above the composer and the Changes panel offer one button that fits the repository:

ButtonWhen
Create PRit has commits and a GitHub remote (github.com, or a GitHub Enterprise host your gh is signed in to)
Publish to GitHubit has no remote yet (commit, create the repository, push)
Push first commita remote exists but nothing is committed
Commit & pushthe remote isn't on GitHub

Each one hands the work to the agent as a normal turn, so every git and network step goes through your approvals.

Prompts Houston writes for you

/review, /agent, the shipping buttons, and a session another chat handed off each send the agent a detailed prompt. The chat shows what you did (for example "/review" or "Create PR") instead of that prompt. Open Instructions sent to the agent under it to read the exact text. The terminal prints a one-line summary in its place.
